# Tab pages

**Status:** Phases 1–3 complete. Tab pages are shipped end-to-end: model,
creation/switching/tabline, and now the lifecycle autocmds, the Lua
`nvim_tabpage_*` surface, and the `showtabline` / last-tab-quit edges.

Tab pages are the last big-ticket item on the windows axis
([architecture.md → *Windows*](../architecture.md#windows)). A **tab page** is a
named collection of windows: each tab owns its own split layout (its own
`WindowTree`), and only one tab is visible at a time. nvim draws a *tabline*
across the top when more than one tab is open, and `gt`/`gT` / `:tabnext` cycle
between them. Switching tabs is the window-layout analogue of switching buffers
or focusing a window: the outgoing tab's state is stashed, the incoming tab's
state goes live.

This mirrors how the codebase already grew: `Editor` went single-buffer →
`BufferStore`, then single-window → `WindowTree`, each time **multiplying the
state and deriving the current one**. Tabs multiply the `WindowTree` and derive
the active one.

## Model

The active tab's window layout stays exactly where it is — live on
`Editor::windows` — the same way the *focused* window's cursor/scroll stay live
on `Editor` while non-focused windows stash theirs in `Window::saved_*`. The
inactive tabs stash their whole `WindowTree`; the active tab's stash slot is
empty.

```rust
/// A tab page's stable, never-reused handle (the `nvim_tabpage_*` id).
pub struct TabId(pub u64);

/// One tab page in tabline order: a stable id plus, *while not active*, its
/// stashed window layout. The active tab's tree is live on `Editor::windows`,
/// so its `tree` here is `None` (the "live current, stash the rest" pattern the
/// focused window already uses).
struct TabSlot {
    id: TabId,
    tree: Option<WindowTree>,
}
```

On `Editor`:

- `windows: WindowTree` — **unchanged**; always the *active* tab's live layout.
- `tabs: Vec<TabSlot>` — every tab in tabline order (one entry until Phase 2).
- `current_tab: usize` — index into `tabs` of the active tab.

A tab switch (Phase 2) is then: `mem::swap` the live `windows` into
`tabs[current_tab].tree`, take `tabs[target].tree` into `windows`, set
`current_tab = target`, then re-clamp the now-live focused window (the same
stash/restore `focus_window` already does for windows). Keeping `windows`
untouched means the entire motion/operator/redraw state machine — all 118
`self.windows` sites — needs **zero** changes.

## Phases

Each phase is independently shippable and black-box testable (the project's only
test style: drive the real server over RPC, assert on `redraw` / `nvim_*`).

### Phase 1 — Model + read-only introspection ✅ (this change)

The state multiplication plus the read side of the `nvim_tabpage_*` surface, so
the model is observable end-to-end without yet being mutable.

- **Core:** `TabId`, `TabSlot`, the `tabs` / `current_tab` fields seeded with one
  tab. Accessors: `current_tab_id`, `tab_ids`, `tab_count`, `tab_is_valid`,
  `tab_number`, `tab_window_ids`, `tab_current_window` (each routes through a
  private `tab_tree(id)` that returns `&self.windows` for the active tab or the
  stashed tree otherwise).
- **Server RPC (read-only):** `nvim_list_tabpages`, `nvim_get_current_tabpage`,
  `nvim_tabpage_list_wins`, `nvim_tabpage_get_win`, `nvim_tabpage_is_valid`,
  `nvim_tabpage_get_number`. A `resolve_tabpage` helper maps handle `0` →
  current, mirroring `resolve_win`.
- **No creation/switch surface yet** — so nothing to stub: there is simply no
  `:tabnew`. All existing window/buffer tests pass unchanged (proof the swap is
  behavior-preserving); new `tabs.rs` tests cover the six read RPCs against the
  single seeded tab.

### Phase 2 — Creation, switching & the tabline (the feature becomes real) ✅

- **Surface:** `:tabnew` / `:tabedit [file]`, `:tabclose`, `:tabonly`,
  `:tabnext` / `:tabprevious` / `:tabfirst` / `:tablast`, normal-mode `gt` /
  `gT` / `{count}gt`, `<C-w>T` (move current window to a new tab), and
  `nvim_set_current_tabpage`. `next_tab_id` and a global `next_win_id` were both
  introduced here, with their first readers, so no dead field.
- **Global window ids:** window-id minting moved off the per-tab `WindowTree`
  onto `Editor::next_win_id`, so a new tab's first window never collides with a
  window in another tab. `nvim_list_wins` now spans **all** tabs (matching
  neovim); `nvim_tabpage_list_wins` / the Lua mirror stay per-tab.
- **Tab switch:** `switch_tab` does the `mem::replace` stash/restore above,
  re-laying the incoming tree and re-entering its focused window (restoring its
  buffer + view, clearing transient state), exactly like `focus_window`. A second
  re-lay settles any cursor-relative float once the cursor is live.
- **Tabline in the `View`:** a `Vec<TabView>` (label = the tab's focused window's
  buffer name + modified flag + window count, per vim's default tabline) and the
  active index, projected only when `tabs.len() > 1` (vim's `showtabline=1`
  default). The server's `relayout` reserves the top row (the windows area shrinks
  by one) when the tabline shows — the top-of-frame analogue of the bottom panel;
  the TUI client paints the tabline into that row and offsets the windows area.
- **`:tabnew` buffer handling:** the new tab's buffer is resolved *before* the tab
  is created (a fresh empty one, the named file reused if already open, or a new
  buffer from disk), so it never reuses-in-place and clobbers the current tab's
  buffer the way an `:edit` of a throwaway buffer would.
- **Last-tab guard:** `:tabclose` refuses the final tab (`E784`); the more
  nuanced last-tab quit rules (`:qa` interaction) land in Phase 3.

### Phase 3 — Lifecycle, Lua & edge semantics ✅

- **Autocmds:** `TabNew` / `TabEnter` / `TabLeave` / `TabClosed` from the
  server-side lifecycle diff (`Server::{last_tab_id, known_tabs}` + a `fire_tab`
  helper mirroring `fire_window`), ordered with the window events as
  `TabNew → TabLeave → WinLeave → … → WinEnter → TabEnter → TabClosed`. The tab
  set is pre-seeded at startup so the initial tab doesn't fire `TabNew`, the
  window analogue.
- **Lua:** the `vim._tabs` mirror the server pushes in `push_buf_mirror` (a
  `TabMirror` per tab: id, window ids, focused window) before each Lua entry; the
  `nvim_tabpage_*` reads resolve against it, and the lone mutation
  (`nvim_set_current_tabpage`) queues a new `TabOp::SetCurrent` drained into
  `Editor::set_current_tabpage` — the same "Lua queues, core mutates" flow as
  `WindowOp`, with a write-through so a read-after-set in the same chunk agrees.
- **Options & edges:** `showtabline` (0/1/2) as a global option, honored by both
  the `:set` ex path and `vim.o.showtabline` (wired through a new
  `Editor::set_global_option_num` + the go-mirror), gating the projected
  `Vec<TabView>` and the reserved top row through one `tabline_visible` helper.
  The last-tab quit rules: `:tabclose` / `:tabonly` refuse the final tab; `:q` on
  a tab's last window closes the *tab* (not the editor) while other tabs remain,
  and only the very last window quits; `:qa` still quits. A runnable
  `examples/tabs/` config + sample file is verified end-to-end (the server test
  sources the real `init.lua` and drives its tab API, autocmds, and
  `showtabline`).

## Out of scope (follow-ups)

`:tabmove` reordering, per-tab cwd (`:tcd`), a custom `tabline` /
`guitablabel` expression, and mouse interaction with the tabline.
