# GitHub Release Pipeline Implementation Plan

**Goal:** Stand up a hand-rolled GitHub Actions release pipeline that builds `bemtvi` for five native targets, publishes a review-gated stable release and a rolling `edge` prerelease, with rust-cache for light incremental builds, SLSA provenance attestation, and git-cliff changelogs.

**Architecture:** One reusable build workflow (`build.yml`) defines the five-target matrix and uploads archives as artifacts. `edge.yml` (on `main` push) and a two-workflow stable flow — `release-prep.yml` (manual PR) + `release.yml` (on merged release PR) — reuse it to publish. CI never pushes to `main`; the stable changelog/version bump lands via a reviewed PR, and merging it auto-tags `v<version>` and publishes in one run.

**Tech Stack:** GitHub Actions, Rust (cargo, musl-static Linux), `Swatinem/rust-cache`, `actions/attest-build-provenance`, `git-cliff`, `peter-evans/create-pull-request`, `gh` CLI.

**Reference spec:** `docs/specs/2026-05-31-release-pipeline-design.md`

**Local validation tools:** `actionlint` (already installed) validates workflow YAML. Install `git-cliff` once to validate `cliff.toml` locally: `brew install git-cliff`.

## File Structure

| File | Responsibility |
| --- | --- |
| `Cargo.toml` | Add `strip = true` to `[profile.release]` (smaller binaries). |
| `cliff.toml` | git-cliff config: conventional-commit grouping, ignores the `edge` tag. |
| `CHANGELOG.md` | Seed file; regenerated by `release-prep.yml` on each stable release. |
| `.github/workflows/build.yml` | Reusable matrix build (5 native targets, musl Linux, rust-cache) → artifacts. The x86_64 macOS row uses `macos-15-intel` (GitHub retired `macos-13` in Dec 2025; `macos-15-intel` is the last free Intel image, available until Aug 2027). |
| `.github/workflows/edge.yml` | On `main` push → rolling `edge` prerelease (overwrites assets) + attestation. |
| `.github/workflows/release-prep.yml` | Manual dispatch → regenerate CHANGELOG + bump version → open `release` PR. |
| `.github/workflows/release.yml` | On merged `release` PR → tag `v<version>` + build + publish stable release. |
| `docs/verifying-downloads.md` | How to verify checksums + provenance attestation. |

- [ ] **Step 1: Create `cliff.toml`**

Create `cliff.toml` at the repo root with this exact content:

```toml
# git-cliff configuration — https://git-cliff.org
# Conventional-commit changelog for bemtvi. The rolling `edge` tag is ignored so
# it is never treated as a release boundary.

[changelog]
header = """
# Changelog

All notable changes to this project are documented in this file.
The format is based on conventional commits.
"""
# Tera template. The `<!-- N -->` group prefixes drive ordering and are stripped
# from the rendered output.
body = """
{% if version %}\
    ## [{{ version | trim_start_matches(pat="v") }}] - {{ timestamp | date(format="%Y-%m-%d") }}
{% else %}\
    ## [unreleased]
{% endif %}\
{% for group, commits in commits | group_by(attribute="group") %}
    ### {{ group | striptags | trim | upper_first }}
    {% for commit in commits %}\
        - {% if commit.scope %}*({{ commit.scope }})* {% endif %}\
            {% if commit.breaking %}[**breaking**] {% endif %}\
            {{ commit.message | upper_first }} ({{ commit.id | truncate(length=7, end="") }})
    {% endfor %}\
{% endfor %}\n
"""
trim = true
footer = ""

[git]
conventional_commits = true
filter_unconventional = false
split_commits = false
protect_breaking_commits = false
filter_commits = false
topo_order = false
sort_commits = "oldest"
# Treat only v-prefixed semver tags as releases; never the rolling edge tag.
tag_pattern = "v[0-9]*"
ignore_tags = "^edge$"
commit_parsers = [
  { message = "^feat", group = "<!-- 0 -->Features" },
  { message = "^fix", group = "<!-- 1 -->Bug Fixes" },
  { message = "^perf", group = "<!-- 2 -->Performance" },
  { message = "^refactor", group = "<!-- 3 -->Refactor" },
  { message = "^docs", group = "<!-- 4 -->Documentation" },
  { message = "^test", group = "<!-- 5 -->Testing" },
  { message = "^chore\\(release\\)", skip = true },
  { message = "^chore|^ci|^build", group = "<!-- 6 -->Miscellaneous" },
  { message = ".*", group = "<!-- 7 -->Other" },
]
```

## Task 3: Reusable build workflow

**Files:**
- Create: `.github/workflows/build.yml`

- [ ] **Step 1: Create `build.yml`**

Create `.github/workflows/build.yml` with this exact content:

```yaml
name: build

on:
  workflow_call:
    inputs:
      version:
        description: "Version string used in archive names (e.g. 0.2.0 or edge)"
        required: true
        type: string

jobs:
  build:
    name: ${{ matrix.target }}
    runs-on: ${{ matrix.runner }}
    strategy:
      fail-fast: false
      matrix:
        include:
          - { target: x86_64-unknown-linux-musl,  runner: ubuntu-latest,   os: linux,   suffix: x86_64-linux-musl,  ext: tar.gz }
          - { target: aarch64-unknown-linux-musl, runner: ubuntu-24.04-arm, os: linux,   suffix: aarch64-linux-musl, ext: tar.gz }
          - { target: x86_64-apple-darwin,        runner: macos-15-intel,   os: macos,   suffix: x86_64-macos,       ext: tar.gz }
          - { target: aarch64-apple-darwin,       runner: macos-14,         os: macos,   suffix: aarch64-macos,      ext: tar.gz }
          - { target: x86_64-pc-windows-msvc,     runner: windows-latest,   os: windows, suffix: x86_64-windows,     ext: zip }
    steps:
      - uses: actions/checkout@v6

      - name: Compute asset name
        shell: bash
        run: echo "ASSET=bemtvi-${{ inputs.version }}-${{ matrix.suffix }}.${{ matrix.ext }}" >> "$GITHUB_ENV"

      - name: Install Rust toolchain
        uses: dtolnay/rust-toolchain@stable
        with:
          targets: ${{ matrix.target }}

      - name: Install musl tools (Linux)
        if: matrix.os == 'linux'
        run: |
          sudo apt-get update
          sudo apt-get install -y musl-tools

      - name: Configure musl C toolchain (Linux)
        if: matrix.os == 'linux'
        shell: bash
        run: |
          TLOW=$(echo "${{ matrix.target }}" | tr '-' '_')
          TUP=$(echo "${{ matrix.target }}" | tr '[:lower:]-' '[:upper:]_')
          {
            echo "CC_${TLOW}=musl-gcc"
            echo "CARGO_TARGET_${TUP}_LINKER=musl-gcc"
          } >> "$GITHUB_ENV"

      - name: Cache cargo + target
        uses: Swatinem/rust-cache@v2
        with:
          shared-key: ${{ matrix.target }}

      - name: Build
        shell: bash
        run: cargo build --release -p bemtvi --target ${{ matrix.target }}

      - name: Package (Unix)
        if: matrix.os != 'windows'
        shell: bash
        run: |
          mkdir -p dist
          tar -czf "dist/$ASSET" -C "target/${{ matrix.target }}/release" bemtvi

      - name: Package (Windows)
        if: matrix.os == 'windows'
        shell: pwsh
        run: |
          New-Item -ItemType Directory -Force -Path dist | Out-Null
          Compress-Archive -Path "target/${{ matrix.target }}/release/bemtvi.exe" -DestinationPath "dist/$env:ASSET"

      - name: Upload artifact
        uses: actions/upload-artifact@v7
        with:
          name: ${{ env.ASSET }}
          path: dist/${{ env.ASSET }}
          if-no-files-found: error
```

Create `.github/workflows/edge.yml` with this exact content:

```yaml
name: edge

on:
  push:
    branches: [main]

concurrency:
  group: edge
  cancel-in-progress: true

permissions:
  contents: write
  id-token: write
  attestations: write

jobs:
  build:
    uses: ./.github/workflows/build.yml
    with:
      version: edge

  publish:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 0

      - name: Install git-cliff
        uses: taiki-e/install-action@v2
        with:
          tool: git-cliff

      - name: Download artifacts
        uses: actions/download-artifact@v8
        with:
          pattern: bemtvi-edge-*
          path: dist
          merge-multiple: true

      - name: Generate checksums
        shell: bash
        run: |
          cd dist
          sha256sum bemtvi-edge-* > SHA256SUMS

      - name: Attest provenance
        uses: actions/attest-build-provenance@v4
        with:
          subject-path: "dist/bemtvi-edge-*"

      - name: Build release notes
        shell: bash
        run: |
          SHA=$(git rev-parse --short HEAD)
          DATE=$(date -u +%Y-%m-%d)
          {
            echo "Rolling build of the \`main\` branch — **not a stable release.**"
            echo
            echo "Built from \`$SHA\` on $DATE."
            echo
            git cliff --unreleased --strip header
            echo
            echo "---"
            echo "Verify a download's provenance:"
            echo '```'
            echo "gh attestation verify <file> --repo davidrios/bemtvi"
            echo '```'
          } > EDGE_BODY.md

      - name: Move edge tag
        run: |
          git tag -f edge
          git push -f origin edge

      - name: Publish edge prerelease
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          if gh release view edge >/dev/null 2>&1; then
            gh release edit edge \
              --target "$GITHUB_SHA" \
              --title "Bleeding edge (main)" \
              --notes-file EDGE_BODY.md \
              --prerelease
            gh release upload edge dist/* --clobber
          else
            gh release create edge dist/* \
              --prerelease \
              --target "$GITHUB_SHA" \
              --title "Bleeding edge (main)" \
              --notes-file EDGE_BODY.md
          fi
```

## Task 5: Release-prep workflow (opens the release PR)

**Files:**
- Create: `.github/workflows/release-prep.yml`

- [ ] **Step 1: Create `release-prep.yml`**

Create `.github/workflows/release-prep.yml` with this exact content:

```yaml
name: release-prep

on:
  workflow_dispatch:
    inputs:
      version:
        description: "Release version, no leading v (e.g. 0.2.0)"
        required: true
        type: string

permissions:
  contents: write
  pull-requests: write

jobs:
  prep:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 0

      - name: Validate version
        shell: bash
        run: |
          VERSION="${{ inputs.version }}"
          if ! [[ "$VERSION" =~ ^[0-9]+\.[0-9]+\.[0-9]+([-.][0-9A-Za-z.-]+)?$ ]]; then
            echo "::error::Invalid version '$VERSION' (expected semver like 0.2.0)"
            exit 1
          fi
          if git rev-parse "v$VERSION" >/dev/null 2>&1; then
            echo "::error::Tag v$VERSION already exists"
            exit 1
          fi

      - name: Install git-cliff
        uses: taiki-e/install-action@v2
        with:
          tool: git-cliff

      - name: Bump workspace version
        shell: bash
        run: |
          VERSION="${{ inputs.version }}"
          # Replace the first top-level `version = "..."` line, which is the
          # [workspace.package] version (dependency versions like
          # `crossterm = { version = "..." }` are not at column 0). awk is used
          # instead of `sed -i '0,/re/'` because the latter is a GNU-only form.
          awk -v v="$VERSION" '!done && /^version = "/ {sub(/"[^"]*"/, "\"" v "\""); done=1} {print}' Cargo.toml > Cargo.toml.tmp
          mv Cargo.toml.tmp Cargo.toml
          grep -m1 -E '^version = ' Cargo.toml

      - name: Refresh Cargo.lock
        run: cargo update --workspace

      - name: Regenerate CHANGELOG.md
        run: git cliff --tag "v${{ inputs.version }}" -o CHANGELOG.md

      - name: Extract notes for PR body
        run: git cliff --tag "v${{ inputs.version }}" --current --strip header > RELEASE_NOTES.md

      - name: Open release PR
        uses: peter-evans/create-pull-request@v8
        with:
          branch: release/v${{ inputs.version }}
          title: "release: v${{ inputs.version }}"
          labels: release
          commit-message: "chore(release): v${{ inputs.version }}"
          body-path: RELEASE_NOTES.md
          add-paths: |
            Cargo.toml
            Cargo.lock
            CHANGELOG.md
```

## Task 6: Release workflow (tag + publish on merge)

**Files:**
- Create: `.github/workflows/release.yml`

- [ ] **Step 1: Create `release.yml`**

Create `.github/workflows/release.yml` with this exact content:

```yaml
name: release

on:
  pull_request:
    types: [closed]

permissions:
  contents: write
  id-token: write
  attestations: write

jobs:
  tag:
    if: >-
      github.event.pull_request.merged == true &&
      contains(github.event.pull_request.labels.*.name, 'release')
    runs-on: ubuntu-latest
    outputs:
      version: ${{ steps.read.outputs.version }}
    steps:
      - uses: actions/checkout@v6
        with:
          ref: ${{ github.event.pull_request.merge_commit_sha }}
          fetch-depth: 0

      - name: Read version from Cargo.toml
        id: read
        shell: bash
        run: |
          VERSION=$(grep -m1 -E '^version = ' Cargo.toml | sed -E 's/version = "([^"]*)"/\1/')
          echo "version=$VERSION" >> "$GITHUB_OUTPUT"

      - name: Create and push tag
        run: |
          git tag "v${{ steps.read.outputs.version }}"
          git push origin "v${{ steps.read.outputs.version }}"

  build:
    needs: tag
    uses: ./.github/workflows/build.yml
    with:
      version: ${{ needs.tag.outputs.version }}

  publish:
    needs: [tag, build]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
        with:
          ref: v${{ needs.tag.outputs.version }}
          fetch-depth: 0

      - name: Install git-cliff
        uses: taiki-e/install-action@v2
        with:
          tool: git-cliff

      - name: Download artifacts
        uses: actions/download-artifact@v8
        with:
          pattern: bemtvi-${{ needs.tag.outputs.version }}-*
          path: dist
          merge-multiple: true

      - name: Generate checksums
        shell: bash
        run: |
          cd dist
          sha256sum bemtvi-* > SHA256SUMS

      - name: Attest provenance
        uses: actions/attest-build-provenance@v4
        with:
          subject-path: "dist/bemtvi-${{ needs.tag.outputs.version }}-*"

      - name: Build release notes
        shell: bash
        run: |
          {
            git cliff --current --strip header
            echo
            echo "---"
            echo "Verify a download's provenance:"
            echo '```'
            echo "gh attestation verify <file> --repo davidrios/bemtvi"
            echo '```'
          } > RELEASE_NOTES.md

      - name: Publish release
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          gh release create "v${{ needs.tag.outputs.version }}" dist/* \
            --title "v${{ needs.tag.outputs.version }}" \
            --notes-file RELEASE_NOTES.md
```

# Verifying downloads

Every released `bemtvi` binary ships with a SHA-256 checksum and a signed
[build provenance attestation](https://docs.github.com/actions/security-guides/using-artifact-attestations)
proving it was built by this repository's release workflow.

## Checksums

Each release (stable and `edge`) includes a `SHA256SUMS` file. After downloading
an archive into the same directory:

```sh
sha256sum --ignore-missing -c SHA256SUMS
```

## Provenance attestation

Requires the [GitHub CLI](https://cli.github.com). Verify an archive against the
attestation GitHub stores for it:

```sh
gh attestation verify bemtvi-0.2.0-x86_64-linux-musl.tar.gz --repo davidrios/bemtvi
```

A successful run confirms the artifact was produced by the `bemtvi` release
workflow at a specific commit, and was not tampered with afterwards.
````

## Notes for the implementer

- **No unit tests here.** This is CI configuration; the project's integration-test harness (`crates/bemtvi-server/tests/editing.rs`) does not apply. Validation is `actionlint` + the live GitHub run in Task 8. Do not add `#[test]` code.
- **Action versions are pinned to major tags** (`@v4`, `@v2`) deliberately — these are first-party/well-maintained actions and major tags get security patches. If you prefer full SHA pinning, that's a reasonable hardening follow-up, out of scope here.
- **`GITHUB_TOKEN` tag pushes don't trigger workflows** — this is why `release.yml` tags *and* publishes in one run instead of relying on a tag-push event. Don't "simplify" it into a separate `on: push: tags` workflow; it would silently never fire.
- **musl env var names**: `CC_<target_with_underscores>` (lowercase) for the `cc` crate, `CARGO_TARGET_<TARGET_UPPERCASE>_LINKER` for the linker. The `Configure musl C toolchain` step derives both from `matrix.target`.
```
