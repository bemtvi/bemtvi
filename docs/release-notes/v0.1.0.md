bemtvi 0.1.0 is the first release: a modal, vim-style editor with Lua plugins, treesitter and LSP, built as an async server with thin clients.

Your vim keystrokes work: modes, motions, operators, text objects, registers, ex-commands and options behave the way your fingers expect. The rest is bemtvi's own. Config and plugins use one documented Lua API, `btv.*`, and the server owns every UI surface (picker, completion menu, statusline, docks, floats), so plugin Lua never runs while a frame is drawn and a slow plugin can't hold up a keystroke.

```sh
bemtvi file.txt        # terminal editor
bemtvi-gui file.txt    # native GUI
```

0.x means the `btv.*` API can still change between minor versions. [The book](https://bemtvi.github.io/bemtvi/) documents every function as of this release.

## What's in 0.1

- **Vim editing**: motions, text objects (tree-sitter function, argument, comment and type objects included), operators with counts and dot-repeat, charwise and linewise Visual, registers with the system clipboard, marks, the jumplist and changelist, `:s`/`:g`, and a branching undo tree with `:earlier`/`:later` by count, time or write.
- **Buffers, windows, tabs and floats**, with soft wrap, smooth scrolling, four fold methods and a native multi-cursor.
- **Treesitter in-process**: incremental highlighting, folds and text objects. `:TSInstall` builds a grammar with a Zig toolchain bemtvi downloads and checks itself, so no C compiler is needed, and grammars load off the editor thread.
- **LSP and diagnostics**: completion, hover, go-to, references, rename, code actions, formatting, semantic tokens, inlay hints and progress, merged across every server on a buffer. Ready-made configs for over 400 servers are in the [bemtvi-lspconfig](https://github.com/bemtvi/bemtvi-lspconfig) plugin.
- **Built-in widgets plugins drive**: a fuzzy picker with preview, a completion engine with async sources, snippets, statusline segments, viewport decorations, docks and `btv.ui` prompts. Every widget's keys go through the keymap engine.
- **Remote editing that doesn't lag**: `bemtvi --daemon` on the remote machine serves files, processes, terminals and language servers, while the editor, your config and your plugins run locally. `:connect user@host` starts it over ssh, and a dropped link reconnects without losing the session.
- **Workspaces**: `bemtvi --workspace <dir>` keeps a directory's tabs, windows and option overrides across restarts.
- **Terminals, quickfix and git**: `:terminal` on a PTY (ConPTY on Windows), quickfix and location lists, and git through a Rust library, with no `git` binary needed.
- **A plugin manager and a test runner**: `btv.plugins` installs and lazy-loads plugins, and `bemtvi --test-plugin <dir>` runs a plugin's `btv.test` specs headlessly. [`examples/`](https://github.com/bemtvi/bemtvi/tree/v0.1.0/examples) has over a hundred runnable examples, each with its own spec.
- **A browser build**: the downloadable `bemtvi-edithost` site runs the whole editor in a browser tab, on its own or attached to a daemon.

|---|---|---|

A truecolor terminal is recommended, and kitty, Ghostty or foot (or WezTerm with `enable_kitty_keyboard`) tells apart chords like `<C-i>` and `<Tab>`.
