# `nx.glob` — a real glob engine, compiled to a cached Rust regex

**Status:** COMPLETE (2026-07-26) — all four phases.

## Problem

nxvim has no glob engine. It has **three** ad-hoc glob matchers, each a different
subset of the syntax, none sharing a line of code:

| Site | What it supports | Gaps |
| --- | --- | --- |
| `crates/nxvim-lua/src/host.rs::glob_match` | exactly **one** `*` | `?`, classes, `**`, braces, a second `*` |
| `crates/nxvim-lua/src/prelude/autocmd.lua::au_one_pattern_matches` | `*`, `?`, `[abc]`, `[!a]`/`[^a]` | `**`, `{a,b}`; hand-rolled Lua-pattern escaping; `pcall`s around malformed classes |
| `crates/nxvim-core/src/editor/quickfix.rs::is_glob` | *detection only* | `:vimgrep` fails loud on any glob argument |

The autocmd one is the worst offender: it **translates globs into Lua patterns** by
`gsub`-escaping Lua magic, then repairing negation spellings (`[!` → `[^`, and
un-escaping a `^` the blanket escape already mangled). It is correct today only
because every documented case is pinned by a test; `**` and `{a,b}` — both of which
users reasonably expect, and which the LSP spec's glob dialect requires — silently
mismatch.

Meanwhile plugins have no glob API at all. A plugin that wants "does this path look
like a test file" re-derives its own matcher in Lua, which is both slow (per-path Lua
pattern work) and a fourth dialect.

## What this adds

One canonical glob engine in the core, and `nx.glob` on top of it.

### Engine: globset as the translator, our own compiled regex

`globset` (BurntSushi, the crate behind ripgrep's `--glob`) already **is** the
glob→regex compiler: `GlobBuilder` parses the pattern and `Glob::regex()` hands back
regex source. We take that source and compile/own the `regex::bytes::Regex`
ourselves rather than using globset's `GlobMatcher`.

That indirection is deliberate, and it is the crux of the path-style requirement
below: `GlobMatcher::is_match` runs the candidate through globset's `Candidate`,
whose separator normalization is `#[cfg(windows)]`-gated on the **host**:

```rust
// globset-0.4.19/src/pathutil.rs
#[cfg(unix)]    fn normalize_path(path) -> { path }              // no-op
#[cfg(windows)] fn normalize_path(path) -> { /* `\` -> `/` */ }
```

For nxvim that is the wrong axis. The daemon/remote session is a tier-1 target, so a
Unix-hosted client can be handed Windows paths off the wire — and a `#[cfg]` decided
at *build* time cannot express "this candidate is a Windows path." Owning the regex
means path style is an explicit, per-call **option**, and matching behaves identically
on every host and in the wasm build.

`globset` is pure Rust, wasm-safe (deps: `aho-corasick`, `bstr`, `log`,
`regex-automata`, `regex-syntax`), and compiles to the same `regex` crate already in
`[workspace.dependencies]`. Note `Glob::regex()` is **byte**-oriented
(`syntax.utf8(false)`), so it must be compiled with `regex::bytes::Regex`, not
`regex::Regex` — which is also the more correct thing to match a path with.

### Path style — explicit, never inherited from the build target

`PathStyle::{Unix, Windows}`, defaulting to the host:

* **Unix** — `/` separates. `\` is the **escape** character in a pattern
  (`backslash_escape = true`) and an ordinary filename byte in a candidate.
* **Windows** — `/` *and* `\` separate. `\` in a pattern is a separator, **not** an
  escape (`backslash_escape = false`, matching globset's own convention), so
  `src\*.rs` is a path. Both pattern and candidate are normalized `\` → `/` in our
  layer before compile / match, so drive letters (`C:/foo`) and UNC paths
  (`//server/share`) ride through as ordinary components.

Because normalization happens in our layer, a Unix host matches Windows paths
correctly and vice versa. Nothing in the prelude models path style today
(`nx.utils.dirname` is `/`-only), so this is the first place the distinction exists.

### `*` stops at `/` by default

`literal_separator = true` — shell / gitignore / LSP-spec semantics: `*.lua` does
**not** match `a/b/c.lua`; `**/*.lua` does. This is globset's non-default, chosen
because it is what everyone expects from every other glob tool.

Vim's autocmd rule is the opposite (`*` crosses `/`), so Phase 2 converges
`autocmd.lua` with an explicit `literal_separator = false` opt-out plus the
`basename` rule below — behavior preserved, syntax gained.

### Caching

A thread-local `RefCell<HashMap<Key, Arc<Glob>>>` in `nxvim_core::glob`, keyed by
the pattern **and every option** that changes the emitted regex (style, ignorecase,
literal_separator, basename, empty_alternates). Both the one-shot Lua calls and the compiled
userdata go through it, so `nx.glob.match(pat, path)` in a hot loop compiles once and
every later call is a regex match. Bounded (`CACHE_MAX`) and cleared wholesale on
overflow rather than growing without limit — a plugin generating patterns per
keystroke must not leak. Glob **sets** are cached the same way, keyed by the joined
pattern list.

Thread-local, not a global `Mutex`: `nxvim-core` stays pure and synchronous, and the
Lua VM is single-threaded, so there is no contention to arbitrate.

## Lua surface (`prelude/glob.lua`)

```lua
nx.glob.compile(pattern, opts) -> Glob    -- reusable compiled matcher
nx.glob.match(pattern, path, opts) -> bool           -- one-shot, cache-backed
nx.glob.set(patterns, opts) -> GlobSet    -- N patterns, one RegexSet
nx.glob.any(patterns, path, opts) -> bool            -- does any pattern match
nx.glob.filter(patterns, paths, opts) -> list        -- keep the matching paths
nx.glob.to_regex(pattern, opts) -> string            -- the translated regex source
nx.glob.is_glob(s) -> bool                           -- does `s` carry a metacharacter
```

`Glob` methods: `:test(path)`, `:regex()`, `:pattern()`.
`GlobSet` methods: `:test(path)`, `:matches(path)` -> list of 1-based indices,
`:patterns()` -> the pattern list as written (so a `:matches` index reads back as the
glob that hit).

`to_regex` **raises** on `basename = true`: that option reduces the *candidate* to its
last component before the regex runs, which no regex can express (with
`literal_separator = false` a `*` crosses `/`, so not even a `(?:.*/)?` prefix), and
the function exists precisely to hand the translation to an engine that will not
perform the reduction. `compile(..):regex()` still answers — it introspects a glob that
*does* reduce.

`opts`: `style` (`"unix"`/`"windows"`, default host), `ignorecase`,
`literal_separator` (default `true`), `basename`, `empty_alternates` (whether `{a,}`
may carry an empty branch).

Candidate paths are matched as **bytes** (`impl AsRef<[u8]>` in the core, any Lua
string at the bridge), so a non-UTF-8 filename matches by its real bytes — that is what
the `regex::bytes` compile is *for*. The pattern is `&str`, because globset's parser is.

An invalid pattern **raises** (no silent stubs) — except `[abc` with no closing `]`,
which globset's `allow_unclosed_class(true)` treats as the literal `[abc`. That is
strictly better than today's autocmd behavior (matches nothing as a glob) and still
satisfies the existing `malformed_glob_class_does_not_abort_the_event_fire` test,
whose assertion is that the exact spelling matches.

## Phases

Phase 1 bundles engine + Lua surface because of the **no-unit-tests** rule: the core
module has no standalone test seam, so it is first observable through `nx.glob`.

* **Phase 1 — engine + `nx.glob`. DONE.** `crates/nxvim-core/src/glob.rs`, the
  `crates/nxvim-lua/src/glob.rs` bridge, `prelude/glob.lua`, and
  `crates/nxvim-server/tests/glob.rs` (24 tests). Plus `examples/glob/`. Verified
  native, `--no-default-features`, and a real `wasm32-unknown-emscripten` check of
  `nxvim-edithost` (globset compiles under emscripten) per the tier-1 rule.
  Mutation-tested: a pattern-only cache key and a host-`cfg` separator normalization
  each fail the suite.
* **Phase 2 — converge `autocmd.lua`. DONE.** `au_one_pattern_matches`'s
  Lua-pattern translation replaced by `nx.glob` at `literal_separator = false` +
  `basename = true`. All 79 pre-existing autocmd tests pass unchanged — including the
  bracket-negation and malformed-class cases, which the engine handles natively. 3 new
  tests cover the gained dialect (`{a,b}`, explicit `**`) and lock the two vim rules.
  `glob.lua` moved ahead of `autocmd.lua` in the prelude load order.
* **Phase 3 — converge `host.rs::get_runtime_file`. DONE.** The one-`*` `glob_match`
  is deleted; the final component compiles through `nxvim_core::glob` (once, outside
  the runtimepath loop). Each directory listing is now **sorted**, so `all = false`
  picks a deterministic first match. A metacharacter-carrying component that does not
  compile falls through to the literal-path branch — not a swallowed error, since a
  real filename may contain `[`, `?` or `{`.
* **Phase 4 — converge `quickfix.rs::is_glob`. DONE.** Deleted for
  `crate::glob::is_glob`. `{a,b}` now counts as a glob, so `:vimgrep` rejects a brace
  pattern loudly instead of looking for a file literally named `{a,b}.txt`.

## Outcome

One engine, one `is_glob`. Workspace: **2952 passing, 0 failures**. Verified native,
`--no-default-features`, and `wasm32-unknown-emscripten` (a real emcc build, whose
harness runs `nx.glob` — braces, `**`, basename, windows style, a non-UTF-8 candidate,
a set, and the fail-loud arm — in the wasm VM).

## Review pass (2026-07-26) — what the four phases got wrong

A review after the fact found two behavior bugs and four documentation/coverage gaps.
All are fixed; each fix is mutation-tested (revert it, and a named test fails).

* **The byte-oriented matching never reached a caller.** The engine compiles to
  `regex::bytes` *because* a path's bytes need not be UTF-8 — but every consumer
  decoded first, so the property was unreachable and, from Lua, a hard error: all four
  bridges did `path.to_str()?`, raising `invalid utf-8 sequence` on a latin-1 filename,
  and `host.rs` matched `to_string_lossy()` (where a bad byte becomes a 3-byte U+FFFD
  that no `?` can line up with). Candidates are now `impl AsRef<[u8]>` end to end —
  core, bridge, and the runtimepath lookup, which reads the real `OsStr` bytes on unix.
  Patterns stay `&str` (globset's parser is), and a non-UTF-8 *pattern* now fails loud
  instead of erroring generically.
* **An uncompilable autocmd pattern failed silently, forever.** `nx.autocmd.create`
  accepted `pattern = "x[z-a]*.lua"`, returned an id, and then the per-fire `pcall` in
  `au_one_pattern_matches` swallowed `invalid range; 'z' > 'a'` on *every* event — the
  autocmd never fired and never said why, against the no-silent-skips rule. Patterns are
  now compiled once at registration (`au_check_patterns`), which raises naming the event,
  the pattern and the reason; the per-fire `pcall` stays as a backstop. It costs nothing
  at fire time — it warms the same cache the matcher reads.
* **`empty_alternates` had zero tests**, despite being wired through the opts struct,
  the cache key, the bridge and the docstring. Covered now, including that the default
  and opted-in spellings coexist (i.e. that it really is in the cache key). The test
  named `..._on_every_option_set` covered 3 of 5 options; it covers all 5 now.
* **`nx.runtime_file` (Phase 3) had zero tests** — the sorted-listing determinism, the
  full dialect, and the literal fallthrough for an uncompilable name were all unverified
  claims. Covered now, byte-exact filename included.
* **Docs corrected:** this plan documented a `braces` option that does not exist (it is
  `empty_alternates`); `?` was documented as "never a separator" unconditionally when it
  obeys `literal_separator` exactly as `*` does — and `literal_separator = false` is the
  live in-tree setting, since that is what `autocmd.lua` passes; and `GlobSet`'s
  `any_basename` carried a stale comment describing *indices* from an earlier design.
* **Two smaller things:** argument errors leaked the private bridge name (`in field
  '_glob_is_glob'`) and now name the public function; the unused `Glob::opts()` accessor
  is gone. One apparent cleanup was rejected on evidence — the `let hit = …; hit` in
  `GlobSet::is_match` looks redundant but is load-bearing (as a tail expression the
  borrowing iterator outlives the `Cow` it borrows, E0597), and now says so.

## Second review pass (2026-07-26) — three more

A pass over the landed feature (workspace green, clippy clean, book renders clean, no
fourth glob dialect left in the tree) found three defects, all in how the surface
*reports* rather than how it matches. Each fix is mutation-tested.

* **`to_regex` silently dropped `basename`.** `nx.glob.to_regex("*.lua", {basename =
  true})` returned the identical source as without the option — a whole-path regex
  handed to a caller who asked for basename semantics, which is exactly the
  looks-like-it-worked failure the no-silent-stubs rule is about. It now raises,
  naming the option and the pattern and saying what to do instead. `Glob::regex()`
  keeps answering (it introspects a glob that really does reduce) and now documents
  that narrower meaning; a `basename` pattern that *carries* a `/` never reduces, so
  it still translates.
* **The invalid-autocmd-pattern raise blamed the prelude.** `au_check_patterns`
  raised at level 2, which is `nx.autocmd.create` — prelude source the caller never
  wrote — so the whole point of registering-time validation ("raise where the caller
  wrote it") landed on `[string "nxvim:prelude/autocmd"]:342`. Level 3 points at the
  config line.
* **`nx.glob.any` / `.filter` blamed a function the caller didn't call.** Both work
  through a compiled set, so a wrong-typed path was reported by `globset:test` — and
  `any` reported `nx.glob.match` instead whenever it was handed a single pattern
  string, two different names for one mistake. Both now check the argument themselves;
  `filter` also reports *which* index is bad, which the bridge cannot know.

Two things were considered and deliberately left alone. An unknown key in an `opts`
table (`{basname = true}`) is still ignored rather than rejected — no `nx.*` opts table
in the prelude is strict, and making this one the exception would be the surprise. And
`au_check_patterns` still rejects a *literal* name that cannot compile as a glob (a
buffer named `{`), where `get_runtime_file` falls through to a literal lookup instead:
the divergence is deliberate, since an autocmd's exact-compare arm makes the raise
recoverable and globset's own message spells the escape (`[{]`).

## Explicitly out of scope

**`:vimgrep` glob *expansion*.** Phase 4 unifies only the *detection* helper;
`:vimgrep src/**/*.rs` still fails loud. Expanding a glob to a file list needs
directory traversal, and the tier-1 remote rule means that has to ride the async fs
seam (`nx.fs.walk` / the daemon's `luafs_op` leg) rather than blocking the editor
thread — a separate feature, not a rider on a matching engine. The fail-loud message
stays until then.
