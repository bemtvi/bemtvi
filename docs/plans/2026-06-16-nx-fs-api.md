# `nx.fs` — a promise-always Lua filesystem API

Status: **done** — 2026-06-16. **Phase 1 (one-shot ops)** and **Phase 2 (`watch`
async-iterator)** both landed. Unblocks the
[nxtree file explorer](2026-06-16-nxtree-file-explorer.md); useful on its own.

A clean, modern, **promise-always** filesystem surface for `nx.*` Lua. One-shot
operations return **promises**; continuous operations (directory change watching)
are **async-iterators** consumed with `nx.await_each` — the same split nxvim
already draws between `nx.run` and `nx.run_stream`. No callbacks anywhere.

## Problem

The full libuv-shaped fs operation set already exists in Rust — `LuaFs`/`StdLuaFs`
(`crates/nxvim-lua/src/luafs.rs`): `scandir` *with entry kind*, `stat`, `lstat`,
`mkdir`, `rename`, `unlink`, `rmdir`, `copyfile`, `realpath`, `read_file`, … — and
is already routed through the host seam (`resolve_lua_fs`,
`crates/nxvim-lua/src/runtime.rs:583`), so it serves local, daemon, and wasm/OPFS
sessions uniformly. But it is **only partially surfaced to Lua**, and incoherently:

- A scattered subset rides `vim.fn.*`: `isdirectory`, `getftime`, `mkdir`, `glob`,
  `filereadable`, `executable`, `exepath`, `realpath`, `resolve`
  (`crates/nxvim-lua/src/install.rs:557-700,2139-2200`).
- Directory listing from Lua is the sync, **name-only** `nx._readdir` (no kind) —
  so a tree must `nx._readdir` then `isdirectory` *every* entry: one stat
  round-trip per file, brutal over the daemon wire. The kind is right there in
  `LuaDirEntry`; nothing exposes it.
- There is **no** Lua surface for `rename` / `remove` / `copy` / `stat`-as-a-table
  / reading or writing file contents.
- A Lua `vim.uv.fs_event` watch surface existed and was **deliberately removed**
  (`crates/nxvim-server/src/effects.rs:1733` — "the Lua `vim.uv.fs_event` surface
  is gone"); the native watcher now drives only the internal per-buffer
  `:checktime`. There is no plugin-reachable watch.

A file tree (and any project/plugin doing fs work) needs a real listing+mutation
API, and ideally a change-watch for auto-refresh.

## Shape: promise for one-shot, async-iterator for continuous

nxvim already made this decision for processes; `nx.fs` mirrors it for internal
consistency:

- **one-shot result → a promise** — like `nx.run`.
- **a stream of results → an async-iterator** consumed with `nx.await_each` inside
  `nx.async` — like `nx.run_stream` (cancel via `:stop()` ↔ `stream:kill()`).

"Promise-always" holds: **no callbacks**. A long-lived watch can't be a single
promise (it resolves once), so it is the *promise-based async-iterator* form — the
same machinery, `await_each` instead of `:next()`.

### What we copy

- **One-shot surface, naming, and the reject-with-`.code` error model →
  `node:fs/promises`** (the de-facto modern promise fs API; Bun mirrors it).
- **The `watch` async-iterator and its `{kind, paths}` event shape → Deno**
  (`Deno.watchFs` / `Deno.readDir` made these async-iterables rather than
  callbacks/EventEmitters — exactly our `await_each` model). `notify`'s
  `EventKind` maps 1:1 onto Deno's `kind`.

Both happen to be what `nx` already looks like.

## Resolved design decisions

**1. `read` returns bytes; `read_text` transcodes (SPLIT — confirmed).**
`LuaFs::read_file` returns `Vec<u8>`. nxvim has a real multi-encoding transcode
seam on every read path. So:
- `nx.fs.read(path)` → raw bytes (a Lua byte-string), no decoding.
- `nx.fs.read_text(path, {encoding="utf-8"})` → transcoded text through the
  encoding seam, **fails loud** on invalid input (no lossy replacement-char
  fallback). The split is principled given the seam already distinguishes the two;
  a single ambiguous `read` would hide the decode step.

**2. `scan` (streaming recursive walk) is DEFERRED — not in v1.**
`readdir` (promise, whole list) covers the tree's per-expand need; dirs are small
and you want the full sorted list anyway. A streaming recursive `scan` is really a
*find-file*/grep-adjacent primitive with no consumer yet. The async-iterator
pattern is already proven by `nx.run_stream` and (here) `watch`, so adding
`nx.fs.scan(path, {recursive})` later is non-breaking. Ship `readdir` + `watch`
now; document `scan` as the planned streaming sibling.

**3. `watch` events are COALESCED in Rust, and carry `{kind, paths}`.**
Two sub-decisions, both forced by what the native watcher does today:
- *Carry paths/kind:* the current `LoopEvent::FsEvent { id, error }` is
  **path-less** — `start_fs_watch` discards `event.kind` and `event.paths`
  (`evloop.rs:300-314`) because its only consumer re-stats a known buffer. A tree
  wants to invalidate *just* the changed subtree, so `FsEvent` must be **extended**
  to carry the classified kind + affected paths. (This is the one piece that is
  *not* pure wiring.)
- *Coalesce, don't flood:* `notify` fires rapid duplicate/burst events (an editor
  writing temp-then-rename emits several). There is no debounce today; the
  idempotent `checktime` consumer didn't need one. A promise async-iterator *would*
  be flooded, so the watcher coalesces a burst per-id within a short window
  (~50 ms) into a single yielded `{kind, paths}` batch with **deduped paths** (and
  a coarsened kind when a burst mixes create+modify). Done in Rust, at the
  `FsEvent` boundary — Lua never sees the raw storm. (Mirrors the daemon's
  lag-tolerant `WATCH_POLL` re-stat philosophy, `daemon.rs:166`.)

## The surface (v1)

```lua
-- ───────── one-shot → promises ─────────  (nx.await inside nx.async, or :next/:catch)

nx.fs.stat(path)              -- → Stat   (follows symlinks)
nx.fs.lstat(path)             -- → Stat   (no follow; type may be "link")
nx.fs.exists(path)            -- → bool   (never rejects — stat-based convenience)

nx.fs.readdir(path)           -- → { { name=, type="file"|"directory"|"link" }, … }  (ONE call, kind incl.)

nx.fs.read(path)              -- → byte-string (raw)
nx.fs.read_text(path, {encoding="utf-8"})  -- → text via the encoding seam (fails loud)
nx.fs.write(path, data)       -- → nil
nx.fs.append(path, data)      -- → nil

nx.fs.mkdir(path, {recursive=true})   -- → nil
nx.fs.rename(from, to)                -- → nil
nx.fs.remove(path, {recursive=})      -- → nil   (rm file / rmdir; recursive walks a subtree)
nx.fs.copy(src, dst, {recursive=})    -- → nil
nx.fs.realpath(path)                  -- → string

-- ───────── continuous → async-iterator ─────────  (for ev in nx.await_each(it) do … end)

nx.fs.watch(path, {recursive=})  -- streams coalesced { kind=, paths={…} } change batches; it:stop()

-- DEFERRED (documented, not built in v1): nx.fs.scan(path, {recursive}) — streaming walk.
```

### Usage

```lua
-- expand a directory (one-shot, the common case):
local entries = nx.await(nx.fs.readdir(node.path))
table.sort(entries, dirs_first_then_alpha)

-- live auto-refresh (continuous):
nx.async(function()
  local w = nx.fs.watch(root, { recursive = true })
  cleanup(function() w:stop() end)
  for ev in nx.await_each(w) do          -- ev.kind, ev.paths (coalesced, deduped)
    tree.invalidate(ev.paths); tree.redraw()
  end
end)()

-- file action with fail-loud error handling:
nx.async(function()
  local ok, err = pcall(nx.await, nx.fs.rename(old, new))
  if not ok then nx.notify("rename failed: " .. err.code, "error") end
end)()
```

## Shapes

**Stat** (off `LuaStat::from_metadata`, `luafs.rs:96`, Lua-flavored):
```lua
{ type = "file"|"directory"|"link", size = <bytes>,
  mtime = <fractional seconds>, atime = …, ctime = …, mode = <int> }
```
`type` reuses `FileKind::as_str` — a string compare, not `isDirectory()` method
calls (the ergonomic Lua form).

**Dir entry:** `{ name = <string>, type = "file"|"directory"|"link" }` — `lstat`
semantics (a symlink reports `"link"`, not its target's kind), matching libuv's
`scandir`.

**Watch event:** `{ kind = "create"|"modify"|"remove"|"rename", paths = { <abspath>, … } }`
— Deno's `FsEvent` shape, post-coalescing.

## Error convention

Promise **rejection**, not a `(nil, err)` tuple — the promise-always way. The
rejection value is an error carrying a libuv/Node-style `.code`
(`ENOENT`/`EACCES`/`EEXIST`/`ENOTEMPTY`/…) plus a human `message`:
```lua
nx.fs.read("/nope"):catch(function(e) assert(e.code == "ENOENT") end)
-- inside nx.async: pcall(nx.await, …), or let it propagate to the runtime reporter.
```
`exists` is the lone exception: resolves `true`/`false`, never rejects.

## Plumbing

- **One-shot ops** bind the existing `LuaFs` methods through `resolve_lua_fs(&sh)`
  and run **synchronously inline** — the same posture as the existing `vim.fn` fs
  builtins (`isdirectory`/`getftime`/`glob`/…, `install.rs:557+`): a local
  `StdLuaFs` is plain fast syscalls, and a daemon session blocks *briefly* on the
  wire (one round-trip per op — and `readdir` is one call total vs. the old
  `nx._readdir` + N×`isdirectory`, so strictly better). The `nx._fs_*` bridges
  return a `(value, err)` pair; the pure-Lua `nx.fs.*` wrappers wrap that in a
  resolved/rejected promise. Because they go through the seam, local / daemon /
  OPFS all work unchanged. `read_text` decodes via `encoding_rs`, failing loud on
  invalid input. *(Offloading a heavy op to the loop actor à la `nx._system_async`
  — fully off-tick — remains a future optimization if a large remote `readdir`
  ever janks; the promise surface already permits it without an API change.)*

  Implemented in: `nx._fs_*` bridges + helpers (`crates/nxvim-lua/src/install.rs`),
  the `nx.fs` wrappers (`crates/nxvim-lua/src/prelude/fs.lua`, registered in
  `runtime.rs`), `encoding_rs` added to `nxvim-lua`. Tests:
  `crates/nxvim-server/tests/fs.rs` (10, all green).
- **`watch`** rides the existing `LoopCommand::FsEventStart { id, path, recursive }`
  / `FsEventStop { id }` + `LoopEvent::FsEvent` (`evloop.rs:70-77,110`). `recursive`
  is already a flag. Required changes:
  1. **Extend `LoopEvent::FsEvent`** to carry `kind` + `paths` (currently dropped
     in `start_fs_watch`), and coalesce a burst per-id (~50 ms, dedup paths) before
     sending.
  2. **Partition the `id` space.** Today `effects.rs:1732` assumes every `FsEvent`
     id is an internal buffer watch (`id - INTERNAL_WATCH_BASE` → `BufferId`).
     Lua-`watch` ids need their own range; the `FsEvent` consumer routes by range:
     internal → `checktime_buffer` (path-less path unchanged), Lua → resolve the
     iterator's next batch. The internal per-buffer watch keeps ignoring the new
     paths field, so its behavior is untouched.
- **Daemon / wasm watch caveat (fail loud).** The native watcher is server-side;
  the daemon already owns a re-stat poll (`WATCH_POLL`, `daemon.rs:166`) for its
  internal watches. Forwarding *Lua* `watch` batches over the daemon wire (and the
  fact that OPFS has no native fs-events at all) is follow-up work. Until it lands,
  `nx.fs.watch` in a daemon/OPFS session must **reject/error explicitly**
  ("fs watch not supported over this transport") — never silently yield nothing
  (no-silent-stubs rule). The one-shot ops have no such gap (the seam already
  serves them remotely).

## Phases

1. **One-shot ops → promises. ✅ DONE (2026-06-16).**
   `stat`/`lstat`/`exists`/`readdir`/`read`/`read_text`/`write`/`append`/`mkdir`/
   `rename`/`remove`/`copy`/`realpath`, each a promise over the synchronous `LuaFs`
   seam (`write`/`append` via fd open+write+close with short-write looping; `remove`
   `{recursive}` and `copy` `{recursive}` walk the tree through the seam). Tests
   (`tests/fs.rs`, 10): readdir kinds, stat type+size, write→append→read_text round
   trip (and on disk), read_text fail-loud `EILSEQ` on invalid UTF-8 while raw
   `read` succeeds, exists true/false (never rejects), mkdir `{recursive}`, rename,
   recursive remove, copy (leaves src), and **`ENOENT` rejection** on a missing path
   (does not silently resolve). `cp` source untouched; no-default-features build
   green; promise/async suites unaffected.
2. **`watch` async-iterator. ✅ DONE (2026-06-16).** `LoopEvent::FsEvent` extended
   with `kind: Option<&'static str>` + `paths: Vec<PathBuf>` (the internal
   per-buffer watch leaves them empty); a second `start_fs_watch_coalesced` arms a
   notify watcher whose backend thread feeds raw `(kind, paths)` into a self-reaping
   tokio task that coalesces a burst over a **10 ms** window (mixed kinds coarsen to
   `"modify"`, paths deduped) — only 10 ms in Rust; a plugin wanting a longer settle
   composes `nx.utils.debounce`. `on_loop_event` routes by `id < INTERNAL_WATCH_BASE`
   → the Lua watch pump (`run_fs_watch_event` → `nx._run_fs_watch`), else the
   unchanged `:checktime` path. New `LoopOp::FsWatch`/`FsUnwatch` (queued by
   `nx._fs_watch`/`nx._fs_unwatch`) → `LoopCommand::FsEventStart`/`Stop` natively;
   the **wasm/serverless build rejects the watch loud** (no native watcher).
   `nx.fs.watch` is a `nx.run_stream`-shaped iterator (`:next()`/`:stop()`) over
   `nx.await_each`. Tests (`tests/fs.rs`, +3): a change yields a `{kind, paths}`
   batch naming the file with a valid kind; `:stop()` ends the iteration; a watch on
   a missing path rejects loud. Internal-watch regression green (buffers 29,
   daemon_watch 2); clippy clean in both feature configs.

   Implemented in: `crates/nxvim-server/src/evloop.rs` (FsEvent fields, coalescing
   watcher, `classify_fs_kind`), `effects.rs` (routing + `apply_loop_op` arms,
   native + wasm), `crates/nxvim-lua/src/{ops.rs,install.rs,runtime.rs}` +
   `prelude/fs.lua` (the Watch stream).

## Out of scope (v1)

- `nx.fs.scan` streaming recursive walk (deferred — decision 2; non-breaking to add).
- Daemon/OPFS `watch` transport forwarding (follow-up; must fail loud until then).
- `chmod`/`chown`/`symlink`/`link`/`utime` (the `LuaFs` trait has some; surface
  on demand, not speculatively).
- A `vim.uv`/`vim.loop` compat shim — intentionally not revived; `nx.fs` is the
  surface (decision: "forget vim.uv shape").
